Choose OpenAI Tool Selection Agent (runtime tool calling) instead of letting OpenAI generate SQL queries
1. Solution Overview
System Objective
Build an AI chatbot system that allows users to search for natural stone products using natural language.
Examples:
"Find white marble slabs"
"Black granite stone”
"Stone for paving"
The system flow:
User
↓
Chatbot UI
↓
OpenAI Tool Selection
↓
REST API
↓
MySQL
The AI is not allowed to access the database directly.

3. Tool Selection Architecture (Recommended)
How It Works
Step 1
User input:
Find white marble slabs
Step 2
OpenAI analyzes the intent:
search_products
Arguments:
{
query: "white marble slabs",
material: "marble",
type: "slab"
}
Step 3
Runtime calls the API:
POST /api/search/products
Step 4
REST API queries MySQL:
SELECT * FROM stone
WHERE material_id = 4
AND type_id = 4
Step 5
OpenAI responds:
I found 12 white marble slabs.
4. Why NOT Use AI-Generated SQL
Risky Approach
User
↓
OpenAI generates SQL
↓
Database
Example:
SELECT * FROM stone
WHERE material='marble'
Main Risks
1️⃣ SQL Injection Risk
AI may generate dangerous queries.
Examples:
DROP TABLE stone
or
DELETE FROM stone
This is a real-world risk.
Evidence
OpenAI recommends not allowing AI to query databases directly.
OpenAI Cookbook:
https://cookbook.openai.com/examples/how_to_call_functions_with_chat_models
OpenAI recommendation:
Use function calling instead of direct database access.
Microsoft Recommendation
Microsoft Azure OpenAI:
https://learn.microsoft.com/en-us/azure/ai-services/openai/how-to/function-calling
Recommendation:
Use tools or APIs instead of allowing the model to generate SQL queries directly.
OWASP Warning About LLM Injection
OWASP Top 10 for LLM:
https://owasp.org/www-project-top-10-for-large-language-model-applications/
Risk:
Prompt injection can lead to data exfiltration or unsafe queries.
5. Architecture Comparison
AI-Generated SQL
User → AI → SQL → Database
Advantages:
Fast setup
Disadvantages:
No SQL control
High security risk
Hard to audit
Unpredictable behavior
Not production-safe
Tool Selection Architecture
User → AI → Tool → REST API → DB
Advantages:
✅ Secure✅ Predictable✅ Controlled SQL✅ Audit logs✅ Scalable✅ Production-ready
Disadvantages:
Requires coding
6. Reasons for Choosing Tool Selection Runtime
Technical Reasons
1️⃣ 100% SQL Control
SQL exists only on the server:
server.js
AI never sees the SQL.
2️⃣ No SQL Injection
Using prepared statements:
pool.execute(sql, params)
3️⃣ Predictable Behavior
AI can only call:
search_products
get_product_detail
get_vietnam_time
No random queries are possible.
4️⃣ Easy Logging
You can log:
Search queries
SQL statements
Parameters
5️⃣ Good Performance
Per request:
1 MySQL query

8. Tool Selection Mechanism (Most Important)
OpenAI does not randomly choose tools.
OpenAI uses semantic matching.
Example:
User:
get the time
Tool:
get_vietnam_time
AI selects this tool.
Example:
User:
show granite stone
AI selects:
search_products
Tool Schema Determines Behavior
Example:
Description:
Search stone products
AI will understand the tool’s purpose.
